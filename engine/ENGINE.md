# THE RH ENGINE — an unstoppable, learning, creative solving machine

**Mandate (Jacob, 2026-07-18):** solve RH. No desk-work-is-done, no "exhausted options,"
no stopping. This is the VTT/BOTG ethos as code. The machine believes — by construction —
that RH can and WILL be solved, and never halts short of a proof.

## The belief is the loop invariant
The ONLY halting state is `PROOF_FOUND`. "Exhausted" is not reachable:
- queue runs low  -> GENERATE new methods (the method space is unbounded).
- K consecutive nulls -> ESCALATE to a different KIND of method (diversify, don't grind).
- a class is eliminated -> that is FUEL (narrows the search), recorded, never re-tried.
- compute/tools run out -> pull more (Membrane, fleet, new papers), never quit.
Elimination = progress. Stagnation = escalation. There is no "give up" transition.

## Four organs
1. GENERATOR (creativity core). Given the FULL state — obstruction map (closed doors + why),
   eliminated CLASSES (e.g. local/factorization methods are provably dead, A14), the
   solved-analog engine (function-field/Selberg/Lee-Yang/Jensen mechanisms + what's missing),
   the entire attack history — an LLM proposes structurally-DIVERSE novel attacks AS RUNNABLE
   CODE. It is seeded to NOT regenerate dead classes. The unbounded generator = "never exhausted."
2. RUNNER. Executes each method's code, captures output. Fleet-aware (Mac + Olympus).
3. JUDGE. Classifies each result: PROOF / LEAD (found structure -> spawn follow-ups) /
   NULL (no signal) / WALL (confirms a known obstruction -> eliminate that class as fuel).
4. LEARNER. Append-only outcome log = long-term memory (never repeats a dead end). Bandit over
   method-FAMILIES: compute flows to what yields structure. Refills the queue from the generator.

## The generative engine (how it stays creative, not confirmation-looping)
Methods are generated by SOLVED-ANALOG MINING (extract the working mechanism from each solved
RH-cousin, find the missing ingredient here, build just that) + CROSS-DOMAIN ISOMORPHISM (map RH
structure onto every field's solved problems) + ADVERSARIAL DIVERSITY (each new batch must be
structurally different from all prior, checked by the judge). The class-elimination results are
fed in so it explores only LIVE regions. Genuinely new > incrementally new, enforced.

## USAGE SAFETY — the hard guardrails (Jacob's #1 concern: never blow the weekly Max quota)
**Principle: RUNNING methods is FREE (local numpy/mpmath, 24/7). Only CREATIVE GENERATION costs.**
So the loop runs free forever and spends Claude RARELY, HARD-CAPPED, PREDICTABLY. A broken/runaway
loop can never eat the week. Enforced in `budget.py`:
- **FREE-first generation:** tries the AI gateway (:7792) / Olympus Ollama BEFORE any paid call. Free = unlimited.
- **PAID hard caps:** ≤3 Claude generations/day, ≥4h between any two, ABSOLUTE.
- **Circuit breaker:** 3 consecutive bad generations in a day → paid OFF for the day (stops runaway waste).
- **Week-usage ceiling:** if all-usage% ≥ 55 (read from `~/tools/usage-tracker.js`), engine goes FREE-ONLY —
  protects the rest of your usage week so a mid-week binge never screws you.
- If free is down AND paid is blocked: generation is SKIPPED (loop keeps running free methods). Never stalls, never overspends.
Net: you can leave it running all night and wake up to ~zero usage spent (just free local compute), unless it
found something worth a capped generation.

## Lit-gate wiring (added 2026-07-28 — closes a real gap, not theoretical)
The heuristic keyword judge in `classify()` had no idea whether a "LEAD" was already-published
territory or a known-dead route — arsenal/t01_route_prefilter's prior-art DB existed but nothing
forced the engine to consult it. `rh_engine.py` now calls `prior_art_override()` after every run:
a DEAD/WALL prior-art hit force-corrects the class to WALL; a KNOWN hit (published, non-dead —
e.g. Jensen/GORTTW territory) forces KNOWN_TERRITORY so rediscovering a published result can
never bump bandit yield as if it were fresh structure. Verified live: an `auto_jensen_ladder`-
style method now gets caught as KNOWN_TERRITORY instead of feeding the bandit.

`engine/lit_recheck.py` re-queries arXiv per tracked topic (Jensen, de Bruijn-Newman, Connes-
Consani, arithmetic Hodge index, etc.) every 14 days and stages new hits in `LIT_WATCH.md` —
the static PRIOR_ART dict is a snapshot, and this is what keeps it from going stale silently over
an indefinite run. First live run (2026-07-28) already surfaced a Feb-2026 paper ("Certified
Failure at Order Five", arXiv:2602.20313) not yet folded into PRIOR_ART's de Bruijn-Newman entry
— staged for review, not auto-merged. Run periodically (cron/loop, e.g. daily) alongside
`run_forever.sh`; it does not touch methods.json and is safe to run independently.

The sibling fix for the human-run 6-Fable Roundtable (a symmetric peer structure, which the
escalation-of-commitment literature measures far worse than asymmetric ones) is
`arsenal/t12_roundtable_gate.py` — a deterministic, non-peer gate any "this is novel" claim must
pass (t01 prior-art clean + a logged lit-check) before it earns REPORT tier instead of CLAIMED.
Peer agreement in the roundtable is not itself evidence; this is the checkpoint outside the room.

## The bound-tier hole — CLOSED (2026-07-28)
Sharper diagnosis from the same design thread, worth keeping verbatim: the entire checking loop
up to this point was Claude checking Claude — Riemann7's terminal session, this engine's judge,
the Roundtable, the Claude Code session watching it — same model family, same blind spot,
correlated failure. Two instances agreeing is not independent evidence. The ONLY genuine outside
check in the whole pipeline is a formal, non-LLM verifier: Arb interval arithmetic, the Lean proof
kernel. `verify_gate.py`'s `type=="bound"` branch was a real hole in that: it re-ran the SAME
script that made the claim and string-matched its own expected output. A script computing the
WRONG object entirely would reproduce its own wrong answer every time — self-consistency, not
verification — and it was a live path to PROOF_FOUND. Closed: `bound` now ALWAYS returns
`handle=False`, no matter what it reproduces. Only `type=PD` (independent Arb re-certification)
and `type=lean` (independent Lean kernel build) can ever grant HANDLE / trigger PROOF_FOUND /
page the phone. Verified adversarially: a `bound` cert engineered to trivially "pass" (script
prints exactly its own `expect` string) is still correctly refused. This is the actual
precondition for Jacob being able to leave the machine running and trust the halt signal alone.
